# Электронные визитки КМЗ

Пилот корпоративного сервиса для самостоятельного размещения на Linux.
Один администратор управляет карточками сотрудников, посетители открывают их
по персональной ссылке или QR без регистрации.

## Возможности

- Белый мобильный дизайн, оригинальный логотип, локальный шрифт Onest.
- Фото или инициалы, Ф.И.О. полностью, должность и подразделение.
- Городской рабочий телефон с отдельным добавочным, мобильный телефон и сайт КМЗ.
- Скачивание контакта vCard, QR в PNG/SVG, отправка или копирование ссылки.
- Закрытый кабинет `/manage/`: создание, редактирование, поиск, предпросмотр,
  публикация и отключение. Новая карточка по умолчанию — черновик.
- Неизменяемые адреса `/c/<uuid>/`. Физическое удаление через кабинет запрещено.
- Отключение закрывает карточку, фото, vCard и QR; скачанные ранее контакты
  и уже сохранённые посетителями фотографии отозвать невозможно.
- Данные и фотографии хранятся в PostgreSQL и отдельном постоянном томе.

## Локальный запуск на компьютере разработчика

Python 3.12, команды ниже для Linux/macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-test.txt
export KMZ_ENV=development
python manage.py migrate
python manage.py createsuperuser
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

В Windows используйте `.venv\Scripts\Activate.ps1` и `$env:KMZ_ENV='development'`.
Кабинет: `http://127.0.0.1:8000/manage/`. Команда seed_demo выводит адреса пяти
вымышленных сотрудников и не меняет существующие записи при повторном запуске.
Телефоны в демо отсутствуют, почта — example.com. В архиве нет готовой базы и
предустановленного администратора. Реальные контакты заполняются в кабинете.

Встроенный браузер чата может отправлять Origin: null. Для прямого локального
запуска предусмотрена совместимость только при DEVELOPMENT=True и DEBUG=True,
loopback-хосте/клиенте и Sec-Fetch-Site: same-origin. CSRF-токен обязателен.
В production этот режим не работает. В Docker с bridge-сетью используйте
обычный браузер, поскольку клиент приложения не имеет loopback-адреса.

## Linux: проверка до появления домена

Нужны Docker Engine и Docker Compose v2. В папке проекта:

```sh
export POSTGRES_PASSWORD="$(openssl rand -hex 32)"
docker compose -p kmz-cards-local -f compose.local.yaml up -d --build
docker compose -p kmz-cards-local -f compose.local.yaml exec app python manage.py createsuperuser
docker compose -p kmz-cards-local -f compose.local.yaml exec app python manage.py seed_demo
```

Сохраните POSTGRES_PASSWORD в защищённом хранилище администратора: тот же пароль
требуется при следующих командах. В этом режиме `.env` и TLS не нужны.
С компьютера администратора откройте SSH-туннель:

```sh
ssh -L 8000:127.0.0.1:8000 user@server
```

Теперь в браузере компьютера доступен `http://127.0.0.1:8000/manage/`.
Это отдельная тестовая среда, доступная только через loopback/SSH: не открывайте
её порт в интернет и не используйте для публичных реальных визиток.
QR в этом режиме содержит loopback-адрес и служит только техническим тестом;
сканирование обычным телефоном не откроет сервер. Для мобильного пилота нужен
доступный телефону HTTPS-адрес: постоянный домен или временный адрес компании.

Остановка без удаления данных:

```sh
docker compose -p kmz-cards-local -f compose.local.yaml stop
```

Рабочая среда ниже использует другой Compose-проект и собственные тома.
Локальные демо-данные в неё автоматически не переносятся.

## Linux: рабочая установка с доменом и HTTPS

1. Распакуйте исходники в отдельный каталог, например `/opt/kmz-cards`.
2. Создайте `.env`: `cp .env.example .env`, затем `chmod 600 .env`.
3. Сгенерируйте два разных значения через `openssl rand -hex 32` для SECRET_KEY
   и POSTGRES_PASSWORD. Замените все CHANGE_ME; приложение откажется запускаться
   с этими заглушками. Секреты не передавайте в чат и не коммитьте.
4. Укажите SERVICE_HOST, ALLOWED_HOSTS и PUBLIC_BASE_URL с реальным доменом.
   PUBLIC_BASE_URL — только origin, например `https://cards.company.ru`, без пути.
5. Получите сертификат у корпоративного администратора/центра сертификации.
   Поместите полную цепочку в `deploy/certs/fullchain.pem`, приватный ключ —
   в `deploy/certs/privkey.pem`. Настройте права ключа. Сертификаты не входят
   в образ Docker и Git. Их обновление организуется отдельно; после замены:
   `docker compose -p kmz-cards exec nginx nginx -s reload`.
6. По умолчанию Nginx слушает только loopback сервера: 8080/8443. Настройте
   корпоративный прокси с TLS-подключением к 8443, правильным SNI и Host.
   Он должен передавать запросы `/manage/` и POST без изменения origin.
   Для прямого обслуживания вместо прокси задайте BIND_ADDRESS=0.0.0.0,
   HTTP_PORT=80, HTTPS_PORT=443 и согласуйте DNS/межсетевой экран. Публичный
   внешний адрес должен соответствовать PUBLIC_BASE_URL.

```sh
docker compose -p kmz-cards config --quiet
docker compose -p kmz-cards up -d --build
docker compose -p kmz-cards exec app python manage.py createsuperuser
docker compose -p kmz-cards exec app python manage.py check --deploy
docker compose -p kmz-cards exec nginx nginx -t
```

Nginx требует сертификаты уже при первом запуске. Пароль администратора задаётся
интерактивно, минимум 12 символов. База и Gunicorn не публикуют порты на хосте.
Заголовок X-Forwarded-Proto доверяется только Nginx внутри Docker: не публикуйте
порт app и не подключайте недоверенные контейнеры к этой сети.
При внешнем прокси ограничитель входа Nginx видит его IP: настройте доверенные
real-IP адреса на инфраструктуре или ограничение входа на самом внешнем прокси.
По возможности ограничьте весь `/manage/` VPN/сетями компании. Нативного SSO нет.

В кабинете создайте пять реальных карточек. По умолчанию они не опубликованы.
Черновик можно открыть через «Предпросмотр», затем включить «Опубликована».
QR PNG/SVG доступны после публикации. Городской номер указывайте в «Рабочий
телефон (городской)», добавочный — в отдельном поле (до 10 цифр, начальные нули
сохраняются). Добавочный без городского номера не принимается. Мобильный
заполняется отдельно. На карточке рабочая ссылка использует tel: с параметром ext;
обработка добавочного при звонке зависит от приложения телефона.

В vCard 3.0 передаются оба номера с типами WORK и CELL, подразделение в ORG,
сайт КМЗ отдельной ссылкой; добавочный сохраняется в примечании, поскольку
универсального отдельного поля добавочного для всех импортёров vCard 3.0 нет.
Полное Ф.И.О. сохраняется как введено, без автоматического определения фамилии.
Сайт КМЗ — общая константа `https://www.kmzlift.ru` в config/settings.py.
Он всегда виден на всех карточках, добавляется в vCard и показан в кабинете
только для чтения. Персональная подмена сайта через форму невозможна.

Индексация запрещена метатегом, X-Robots-Tag и robots.txt. Это не защита от
обладателей ссылки: публикуйте только согласованные рабочие данные.

## Тесты

Локально: `KMZ_ENV=development python manage.py test`.

Проверка с PostgreSQL на Linux — **в отдельном Compose-проекте**, не в рабочем:

```sh
docker compose -p kmz-cards-qa -f compose.yaml -f compose.test.yaml run --build --rm app
```

Нужен заполненный `.env`. Команда использует отдельный том БД проекта kmz-cards-qa;
тестовая БД называется test_kmz, рабочая kmz проекта kmz-cards не затрагивается.
Образ тестов дополнительно устанавливает zxing-cpp для независимого чтения QR.

Автотесты проверяют доступ и права, стабильность адреса, отключение карточки и
фото, очистку изображений, экранирование HTML, vCard UTF-8 и переносы, PNG/SVG QR,
неизменность канонического адреса при другом Host, безопасные настройки и demo seed.

## Резервное копирование и восстановление

Команды предназначены для рабочего compose.yaml, не compose.local.yaml.
Копирование кратковременно останавливает app/nginx для согласованности базы и
фото и затем запускает их снова. Выполняйте в согласованное время обслуживания.

```sh
COMPOSE_PROJECT_NAME=kmz-cards sh deploy/backup.sh
```

Архивы создаются в backups/<UTC-время>/ с контрольными суммами и COMPLETE.
Незавершённую копию без COMPLETE не используйте. Копии содержат персональные
данные и хеши паролей: храните ограниченно, шифруйте и копируйте вне сервера.
Отдельно сохраняйте `.env`, сертификаты и эту версию исходников в защищённом
хранилище. Автоматическое удаление старых копий не выполняется.

Пример ежедневного задания cron (настройте путь/логи/срок хранения):

```cron
0 3 * * * cd /opt/kmz-cards && COMPOSE_PROJECT_NAME=kmz-cards sh deploy/backup.sh >> /var/log/kmz-cards-backup.log 2>&1
```

Проверка восстановления — в **новом пустом** Compose-проекте:

```sh
docker compose -p kmz-cards-restore-test build app
COMPOSE_PROJECT_NAME=kmz-cards-restore-test sh deploy/restore.sh /absolute/path/backups/TIMESTAMP --confirm-empty-target=kmz-cards-restore-test
```

Скрипт проверяет SHA256SUMS и отказывается работать с непустой базой или томом
фотографий. Он не удаляет существующие данные. Для реального восстановления
также используйте новую среду; после проверки администратор переключает трафик.
После сбоя восстановления частично заполненную среду не используйте повторно.

В новой среде выполните миграции/collectstatic отдельной командой, пока Nginx
выключен, и сравните число карточек, UUID, рабочие поля и фото с исходной средой:

```sh
docker compose -p kmz-cards-restore-test run --rm --no-deps app python manage.py migrate
docker compose -p kmz-cards-restore-test run --rm --no-deps app python manage.py collectstatic --noinput
docker compose -p kmz-cards-restore-test run --rm --no-deps app python manage.py shell -c 'from cards.models import EmployeeCard; print(EmployeeCard.objects.count())'
```

Не запускайте nginx восстановления с теми же портами, что у рабочей среды:
используйте другие HTTP_PORT/HTTPS_PORT и изолированный тестовый адрес/сертификат.

## Домен и финальные QR

При смене домена измените PUBLIC_BASE_URL, ALLOWED_HOSTS, SERVICE_HOST,
сертификат и CSRF origin (он формируется из PUBLIC_BASE_URL), затем:

```sh
docker compose -p kmz-cards up -d --force-recreate app nginx
```

**Редактирование данных сотрудника не меняет QR. Смена домена меняет QR.**
Не печатайте тестовые QR. Для сохранения уже напечатанных QR при смене домена
требуется работающий HTTPS-редирект на старом адресе, включая прежние /c/<uuid>/.

## Приёмка на сервере компании

- Проверить главную страницу и кабинет по HTTPS, вход/выход и редактирование.
- Создать 5 карточек, проверить через мобильный интернет и VPN-политику кабинета.
- Сохранить vCard на настоящих iPhone/Android: кириллица, телефон, email, должность.
- Скачать PNG/SVG, распечатать пробный QR и открыть камерой телефона.
- Изменить телефон, проверить тот же QR; отключить визитку, проверить старые
  ссылки на карточку, фото, контакт и QR в новой вкладке.
- Перезапустить контейнер app и проверить сохранность данных/фото.
- Выполнить резервное копирование и восстановление в отдельную среду.

## Ограничения этой поставки

Результаты фактических проверок перечислены в VERIFICATION.md. Локальные
автотесты не заменяют проверку Linux/Docker/PostgreSQL, реальных мобильных
устройств, сети компании, сертификатов и печати. Реальные сотрудники пока
не загружены. Мобильного приложения, Wallet, NFC, оплаты и SSO в пилоте нет.
