# Проверки поставки

Дата: 30 октября 2026 года. Среда разработки: Windows, Python 3.12,
Django 5.2.18, SQLite. Сервис на сервер компании ещё не установлен.

## Выполнено

- `python manage.py test`: 40 тестов, все проходят.
- PNG QR прочитан независимым zxing-cpp. SVG независимо преобразован из
  геометрических прямоугольников в растр и прочитан тем же декодером.
- Проверены права администратора, включая запрет массового отключения
  пользователю с правом только просмотра; черновики, отключение, фото, vCard.
- Проверена UTF-8 vCard с кириллицей, переносами и специальными символами.
- Проверено, что изменение данных/Host не меняет канонический адрес QR.
- Проверены отбрасывание не-изображений, размер загрузки, перекодирование
  фото без EXIF и обезличенные имена файлов.
- `python manage.py makemigrations --check --dry-run`: изменений не требуется.
- `python -m compileall -q cards config`: успешно.
- `python manage.py collectstatic --noinput`: 133 статических файла.
- Локальный сервер зарегистрировал HTTP 200 для визитки, CSS, JavaScript,
  логотипа, настоящего Onest и vCard. Сервер предпросмотра остановлен после QA.
- YAML-файлы трёх Compose-конфигураций прочитаны PyYAML без ошибок синтаксиса.
  Это не заменяет `docker compose config` и запуск контейнеров.
- Настоящий Onest из Google Fonts поставляется локально с OFL-лицензией.

## Проверка production-настроек

`python manage.py check --deploy` выполнена с тестовыми переменными production,
без подключения к реальному PostgreSQL. Остались ровно два предупреждения:

- security.W005: HSTS не распространяется на все поддомены.
- security.W021: HSTS preload выключен.

Оба параметра намеренно не включены до согласования доменной политики компании.
Сам HTTPS, Secure cookies, HSTS для выбранного хоста, DEBUG=False и явные
ALLOWED_HOSTS настроены. Заглушки секретов не допускаются в production.

## Требуется проверить на Linux и устройствах

- Docker отсутствует в среде разработки: сборка образов, `docker compose config`,
  Nginx, PostgreSQL и сохранность томов после перезапуска не проверены исполнением.
- Shell из Git for Windows не запускается из-за ограничения Windows namespace
  ACL, поэтому `sh -n` и сами backup/restore не были выполнены. На Linux сначала
  выполните `sh -n deploy/backup.sh deploy/restore.sh`, затем проверку копии и
  восстановления в новый изолированный Compose-проект.
- Доступ к in-app browser через инструмент не получен; визуальная проверка
  публичной страницы на 320/390/768 px и клавиатурных действий остаётся открытой.
  Позднее доступ к вкладке кабинета получен, и вход/список сотрудников проверены
  непосредственно во встроенном браузере (см. исправление ниже).
- Проверка настоящих iPhone/Android, мобильного интернета, бумажного QR,
  корпоративного домена, TLS-сертификата и VPN-политики ещё не выполнена.

Поставку следует считать кандидатом для внутреннего пилота после этих проверок,
а не уже введённым в эксплуатацию сервисом. Порядок установки и приёмки — README.md.

## Независимое ревью

Критических и существенных замечаний не найдено. Ревьюер независимо повторил
все 25 тестов. После ревью добавлен перенос длинной должности/названия компании
и этот отчёт. Осталось небольшое неудобство: стандартная ссылка на уже загруженную
фотографию в форме администратора ведёт на закрытый /private-media/ и возвращает
404. Для просмотра фотографии используйте «Предпросмотр» визитки; публичный
доступ к каталогу фото намеренно не открывается.

## Исправление входа во встроенном браузере

Браузер передавал Origin: null без Referer, с Sec-Fetch-Site: same-origin.
Это вызывало штатный отказ Django CSRF 403. Добавлена совместимость только
для прямого локального запуска: DEVELOPMENT=True, DEBUG=True, путь /manage/,
loopback-адрес и хост, Origin null, браузерная метка same-origin.
Во всех остальных случаях правила Origin остаются исходными. Проверка
CSRF-токена и cookie не отключается; production отказывает таким запросам.
Пять регрессионных тестов прошли. Вход и список пяти сотрудников проверены
прямо во встроенном браузере. Сервер оставлен запущенным по просьбе пользователя.

## Расширение редактируемых полей

По запросу пользователя добавлены подразделение, отдельный добавочный к рабочему
номеру и мобильный телефон. Фото/полное Ф.И.О./должность/сайт КМЗ — основные поля
редактора. Остальные прежние поля оставлены в свёрнутом разделе «Дополнительно».
Миграция 0002 применена к запущенной локальной базе, UUID/ссылки и прежние данные
сохраняются. Новые поля пустые до заполнения администратором.

Пять новых тестов проверяют сохранение через кабинет, публичные поля и ссылки,
валидацию добавочного и мобильного, экспорт двух номеров/подразделения/сайта и
открытие старых карточек с пустыми новыми полями. Все 35 тестов прошли.
Редактор с новыми полями проверен в живом встроенном браузере.
Автодобор добавочного и импорт на настоящих телефонах остаются непроверенными.

## Общий сайт КМЗ

По уточнению пользователя сайт теперь является константой https://www.kmzlift.ru.
В кабинете ссылка доступна только для чтения, на всех карточках отображается
автоматически и передаётся в vCard. Прежнее поле в базе сохранено как неиспользуемое
и нередактируемое, чтобы обновление не удаляло ранее введённые данные.
Миграция 0003 применена локально. Два новых регрессионных теста проверяют общую
ссылку для пустых/старых данных и запрет подмены при отправке формы. Все 37 тестов
прошли.

## Единый формат телефонов

Рабочий и мобильный номера приводятся к +7 (XXX) XXX-XX-XX в редакторе и при
серверном сохранении, а также при отображении прежних корректных номеров.
Добавлены 3 теста нормализации обоих полей, отказа для неполных/лишних цифр и
сохранения пустых полей/нулей добавочного. Все 40 тестов проходят.
В живом редакторе проверено оформление полного номера через 8 и 10 цифр
мобильного. Проверочные данные не сохранялись; реальные карточки не менялись.
